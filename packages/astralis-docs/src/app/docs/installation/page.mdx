# Installation

Install the package, import one stylesheet, wrap your app. That's the whole setup.

## Requirements

| | |
| --- | --- |
| React | `^19.1` (with `react-dom`) |
| Build tooling | None: no plugins, no preprocessors, no theme compiler |

Astralis ships **precompiled CSS**: every class any component can emit is
already in the stylesheet, generated and verified at the library's own build
time. Your bundler just serves a `.css` file.

## The short way

The [CLI](/docs/cli) does all three steps below for you. For a new project:

```bash
npx astralis-cli create my-app
```

It runs the official `create-next-app` or `create-vite` prompts, then wires
Astralis into the result: stylesheet imported, provider mounted, ready to
run. For a project you already have:

```bash
npx astralis-cli init
```

Same edits, made in place. Pass `--dry-run` to see them first.

If you'd rather do it by hand, or the CLI doesn't recognise your setup, the
three steps are below. That's all `init` is doing.

## By hand

These three steps work in any React 19 project. If yours is
[Next.js](#nextjs-app-router) or [Vite](#vite--spa), its own section below has
the whole file.

### 1. Install the package

```bash
pnpm add astralis-ui
# or: npm install astralis-ui / yarn add astralis-ui
```

### 2. Import the stylesheet (once)

```tsx
import "astralis-ui/styles.css";
```

Do this at your app's entry point (root layout in Next.js, `main.tsx` in
Vite). One import covers every component, both themes and all responsive
variants.

### 3. Wrap your app in the provider

```tsx
import { AstralisProvider } from "astralis-ui";

export function App({ children }) {
  return <AstralisProvider defaultTheme="system">{children}</AstralisProvider>;
}
```

`AstralisProvider` owns theming: it resolves light/dark (including the
`"system"` preference), persists the user's choice to `localStorage`, and,
if you pass a brand color, derives the full shade scale at runtime. Details
on the [Theming](/docs/theming) page.

### 4. Check it worked

Start your dev server and put a button on a page:

```tsx
import { Button } from "astralis-ui";

<Button colorScheme="brand">Hello</Button>;
```

- **A plain, unstyled button** means the stylesheet isn't imported in the file
  your app starts from.
- **An error that says `useTheme must be used inside an AstralisProvider`**
  means the provider isn't around your app yet.

## Next.js (App Router)

First install the package, from your project's root:

```bash
pnpm add astralis-ui
# or: npm install astralis-ui / yarn add astralis-ui
```

Then open your root layout: `app/layout.tsx`, or `src/app/layout.tsx` if your
project has a `src` folder. With route groups or locales it is one folder down,
such as `app/[locale]/layout.tsx`. Import the stylesheet after your other
imports and put the provider around `{children}`. The provider is a client
component, but your pages stay server components: children pass straight
through.

```tsx
// app/layout.tsx
import { AstralisProvider } from "astralis-ui";
import "astralis-ui/styles.css";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <AstralisProvider defaultTheme="system">{children}</AstralisProvider>
      </body>
    </html>
  );
}
```

### Avoiding the dark-mode flash

The provider applies the `.astralis-dark` class after hydration, so a user
who prefers dark can see one light-themed frame first. To paint dark from the
very first frame, run this tiny inline script before the body renders (it
reads the same storage key the provider uses):

```tsx
const themeInit = `(function(){try{var t=localStorage.getItem("astralis-ui-theme");var d=t==="dark"||((!t||t==="system")&&window.matchMedia("(prefers-color-scheme: dark)").matches);if(d)document.documentElement.classList.add("astralis-dark");}catch(e){}})();`;

// inside <body>, before your app:
<script dangerouslySetInnerHTML={{ __html: themeInit }} />
```

The constant goes after the imports of `app/layout.tsx`. The script changes
`<html>` before React starts, which is why `<html>` above has
`suppressHydrationWarning`. This documentation site uses exactly this pattern.

To check it all, [put a button on a page](#4-check-it-worked).

## Next.js (Pages Router)

Install the package as above, then open `pages/_app.tsx` (or
`src/pages/_app.tsx`), and create it if you have none. Global stylesheets may
only be imported there.

```tsx
// pages/_app.tsx
import type { AppProps } from "next/app";
import { AstralisProvider } from "astralis-ui";
import "astralis-ui/styles.css";

export default function App({ Component, pageProps }: AppProps) {
  return (
    <AstralisProvider defaultTheme="system">
      <Component {...pageProps} />
    </AstralisProvider>
  );
}
```

`astralis init` edits App Router layouts only, so with the Pages Router this is
always done by hand. [Check it worked](#4-check-it-worked) the same way.

## Vite / SPA

First install the package, from your project's root:

```bash
pnpm add astralis-ui
# or: npm install astralis-ui / yarn add astralis-ui
```

Then open your entry file. It is the one `index.html` loads, usually
`src/main.tsx`. Add the two `astralis-ui` imports and put the provider around
`<App />`, inside `<StrictMode>` if you have it:

```tsx
// src/main.tsx
import { createRoot } from "react-dom/client";
import { AstralisProvider } from "astralis-ui";
import "astralis-ui/styles.css";
import App from "./App";

createRoot(document.getElementById("root")!).render(
  <AstralisProvider defaultTheme="system">
    <App />
  </AstralisProvider>,
);
```

The Vite template's own `src/index.css` centres the page and sets its colours.
Remove those rules, or they will fight the theme.

To check it all, [put a button on a page](#4-check-it-worked).

## Using Astralis alongside your own styling

Whatever your app already uses (a utility framework, CSS Modules, plain
stylesheets), Astralis coexists with it. Every Astralis class is namespaced
under an `astralis:` prefix internally, so the library's styles can never
collide with your own, and your styling setup never needs to know Astralis
exists. You can also pass your own classes to any component via `className`;
see [Style Props](/docs/style-props) for how conflicts are resolved.

## Tree-shaking

The package publishes one ES module per component with a `sideEffects`
declaration, so bundlers drop everything you don't import. Importing a
Button ships the Button, not the library.

## Tooling

Two things worth setting up once, both covered on their own pages:

- **[The CLI](/docs/cli)**: beyond `create` and `init`, it copies
  [blocks](/blocks) into your project (`npx astralis-cli add dashboard-01`) and
  generates a static theme stylesheet from a brand seed.
- **[AI agents](/docs/ai-agents)**: `npx astralis-cli connect-mcp` points
  your coding agent at a server that serves these docs, so it writes against
  the current component API instead of guessing at one.
